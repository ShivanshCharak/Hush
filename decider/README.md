# Local Decider

The Decider accepts one 20-event window, builds code-computed count features, wraps the serialized records as untrusted `DATA`, and requests schema-constrained JSON from the local Ollama chat API. It defaults to model `qwen3:1.7b` and requests output-token log probabilities for the `speak` decision confidence.

Make the configured model available in Ollama before running the full evaluator (for example, `ollama pull qwen3:1.7b`, then start the local Ollama service). Configuration can be changed with `DECIDER_MODEL`, `OLLAMA_BASE_URL`, and `DECIDER_TIMEOUT_SECONDS` (per-window request timeout; default 120 seconds). Increasing the timeout lets slow inference finish, but the evaluator still measures actual latency against the locked p50/p95 targets.

The schema is in `schema.json`. Model output must contain exactly `speak`, `kind`, and `evidence_ids`; a speaking decision cites one event ID from the current window. In the stream processor, a window with no event passing the cheap event prefilter is forced silent without a model call. For windows that pass, Ollama returns `speak`, `kind`, and evidence. This is a prefilter-gated model detector, not an ungated model-only detector. The rules detector remains available as a baseline. See `eval/phase2_eval.py` for dev-only evaluation.

Before inference, source event IDs are replaced with per-window positions (`1` through the window size). The adapter maps a cited position back to the original event ID before validating and recording it. This keeps source IDs and their numeric patterns from acting as accidental model features while preserving citations in evaluation output.

The pattern header records code-computed context for same-account brute force, credential stuffing, profile-ID access, scanner behavior, and decoded SQLi/XSS/traversal signatures. The prompt tells the model to treat this header as supplementary evidence, but the Phase 2 8B artifact used a stricter confirmed-candidate gate: 200/360 windows without a confirmed header candidate were skipped and recorded silent. On the remaining 160 candidate windows, the model returned `speak=true` for all 160, matching the rules baseline's speak decisions; its kind differed from the baseline on 16. That artifact therefore supports a rules-gated kind-classification result, not a claim that the 8B model independently improved speak detection. The later 1.7B and 4B artifacts called the model on all 360 windows. The adapter validates cited events and fails closed on malformed or invalid output. Ollama currently requests a 4096-token context; older artifacts may record 8192. Confidence uses normalized true-vs-false log-probabilities at the generated `speak` token when both alternatives are available in Ollama's top-token data; repaired responses can still have a score if that token is present.

Phase 2 saves each completed model window to `eval/runs/.phase2_checkpoint.json`. After a timeout or interruption, rerun the same evaluator command; it automatically resumes if the model, prompt, schema, and dev data still match. Use `--fresh` to discard a compatible checkpoint and start over. Checkpoints are removed after a complete run. The original 2026-10-19 run that stopped after 316 windows did not contain per-window predictions, so it cannot be resumed; checkpointing applies to subsequent runs.

## Low-memory Ollama hosts

On a host with limited system RAM, llama-server's host-memory prompt cache can grow to its default 8 GiB even when `OLLAMA_NUM_PARALLEL=1`. This is separate from the model KV cache; `OLLAMA_KV_CACHE_TYPE` does not cap the prompt cache. For the project machine, cap it at 1 GiB by adding `Environment="LLAMA_ARG_CACHE_RAM=1024"` to the Ollama systemd service override, then reload and restart the service. The tradeoff is more prompt recomputation and slower inference. Check the Ollama runner log for a cache limit of `1024.000 MiB` before rerunning Phase 2. This workaround is based on the [upstream Ollama issue and llama.cpp environment-variable workaround](https://github.com/ollama/ollama/issues/18264).
